# Lifeline

> 用一张专辑图，标记你的人生坐标。寻觅、收录、定格成章。

一个纯前端、零依赖的专辑海报生成器。搜索专辑、拖拽排序、选好画幅，一键导出你的 Top Albums 海报。

## 这是什么

如果你在网易云、Spotify 或 Apple Music 里存过一堆喜欢的专辑，Lifeline 可以把它们排成一张海报：

搜到专辑 → 拖成你心里的名次 → 选画幅和背景 → 导出图片。

不用注册，不用登录，不联网也能打开（搜索需要联网）。列表存在你自己的浏览器里，不会上传到任何服务器。

<details>
<summary>点这里看效果长什么样</summary>

生成的成品是横竖各 2400px 的高清图，有**六种**排版：

*专辑模式*
- **阶梯排版** — 前排大、后排小，第 1 名最显眼
- **方形网格** — 正好 9 / 16 / 25 张时自动排成方阵
- **诗页堆叠** — 两张纸错位叠放，标题压在纸上、落款居中在纸下，像一页装裱好的信笺

*单曲模式*（打开「单曲模式」开关）
- **九宫格数字叠加** — 9 首以内，巨大半透明排名数字压在封面上，白标签写曲名
- **列表串烧** — 10 首以上，竖长条，封面几乎顶满行高，每行「大数字 + 方形封面 + 曲名/歌手名」

配色有三套：深邃黑、极简白、米色信笺。
标题字体 10 款可选，大小三档可调。

</details>

## 特性

- **专辑搜索** — 通过 iTunes Search API 检索专辑，实时返回封面
- **单曲模式** — 一个开关切到单曲搜索，海报换成九宫格数字叠加 / 列表串烧两套版式
- **导出歌单** — 把海报上的排名导出成标准曲目清单（剪贴板 / `.m3u8` / `.txt`），并给出转成平台歌单的逐步操作
- **五档画幅** — 9 / 16 / 25 / 50 / 100 张，正方形数量自动生成正方形画布
- **阶梯式排版** — 前大后小，排名靠前的位置尺寸更大，权重一眼可辨
- **零空洞算法** — 数量不足时自动重算行列比例，不留空白格
- **手动补位** — 搜不到的专辑可本地上传图片，点空格精准填入对应名次
- **拖拽排序** — 长按进入移动模式，点目标格即可交换
- **背景墙** — 28 张精选专辑封面，四排反向无缝滚动，深色渐变蒙版压暗
- **背景主题** — 深邃黑 / 极简白 / 米色信笺，切换后文字颜色自动适配
- **六种版式** — 自动 / 方形网格 / 阶梯排版 / 诗页堆叠 + 单曲的九宫格 / 列表串烧
- **诗页堆叠** — 两张纸错位叠放，双线框、投影分层，标题自动折行，作者名居中落款
- **标题字体与字号** — 10 款中英文字体（含 Anton），标准 / 偏大 / 超大三档字号
- **即选即看** — 改主题、字体、字号、布局均即时重绘，无需重新生成
- **本地持久化** — 列表与设置存于 IndexedDB，关掉浏览器也不丢

## 快速开始

**方式一：直接用**

打开 👉 **https://limbkins.github.io/lifeline/**

无需安装，手机和电脑都能用。手机上生成后长按图片即可存入相册。

**方式二：下载到本地用**

无需构建、无需安装任何依赖：

```bash
git clone https://github.com/Limbkins/lifeline.git
cd lifeline
open index.html        # macOS
# 或直接双击 index.html
```

也可以起一个本地服务器（部分浏览器对 `file://` 更严格）：

```bash
python3 -m http.server 8000
# 访问 http://localhost:8000
```

## 使用说明

1. 在搜索框输入专辑名或艺人名，回车或点放大镜
2. 点搜索结果加入列表，可用「手动添加」上传本地图片
3. 点空格子 → 高亮 → 再点搜索结果，会精准填入该名次
4. 点已有封面可替换或删除；长按拖动可调整顺序
5. 选择数量档位，填写标题与作者，点「生成图片」导出海报

**想排单曲？** 打开「我的列表」旁的「单曲模式」开关：
搜索会切到单曲（先按艺人匹配拿全量，匹配不到再按曲名多地区搜），
海报自动换成 9 首以内九宫格、10 首以上列表串烧。
切换模式**不会清空列表** —— 专辑和单曲混在一起也能出图。

**想变成歌单？** 点「导出歌单」，三选一。三种格式导出的都是**曲目清单**（不含音频文件），
拿到清单后再用 [Soundiiz](https://soundiiz.com) 之类的工具转成平台里的歌单：

| 选项 | 用途 |
| --- | --- |
| 复制到剪贴板 <sub>推荐</sub> | 一行一首 `艺人 - 曲名`。粘进 Soundiiz 的 **From Plain Text** 即可，不用先存文件 |
| `.m3u8` 文件 | 含曲名、歌手、时长和 Apple Music 直链。Soundiiz 可直接读；VLC、MusicFree 也能播 |
| `.txt` 文件 | 内容和「复制」一样，只是存成文件。适合要先改几行再导入 |

点完任一选项，对话框**不会关**，会原地把内容换成该格式的分步操作说明 ——
包括 Soundiiz 里每一步点哪个按钮、免费版每次 200 首的限制、以及如何扫码连接网易云。

**导进网易云音乐**有两条路：走 Soundiiz（扫码连接，按曲库真匹配，最准），
或者用网易云 App 的「我的 → 三点 → 一键导入外部音乐 → 截图导入」，直接选这张海报
（OCR 认字，所以海报上字越大越准）。

> Apple 的「音乐」App **不认** `.m3u8` 里的网页链接。它的 `File > Library > Import Playlist`
> 只识别本地音频文件路径，导入纯链接会得到一张空歌单。

## 技术说明

整个应用是**一个 `index.html` 文件**，样式、逻辑、资源引用全部内联。

| 项目 | 说明 |
| --- | --- |
| 数据源 | [iTunes Search API](https://performance-partners.apple.com/search-api)（按查询语种动态选地区） |
| 存储 | IndexedDB（列表数据）、localStorage（偏好设置） |
| 渲染 | 原生 Canvas 2D 绘制海报 |
| 字体 | Fontsource CDN 按需加载，中文字库分片下载 |
| 依赖 | 无 |

### 几个实现细节

**`file://` 下必须走 JSONP。** 直接用 `fetch` 请求 iTunes 会被 CORS 拦截 —— 本地文件的 origin 是 `null`，而 iTunes 不返回 `access-control-allow-origin` 头。因此搜索走 JSONP（动态插入 `<script>`）而非 `fetch`。

**背景墙用 `collectionId` 直取。** 按专辑名搜索容易匹配到同名单曲、EP 或翻唱版本。这里预先解析出 28 个 `collectionId` 写死在数组里，用 `/lookup?id=a,b,c...` 批量取图，稳定且精确。

**封面按设备像素密度取图。** 按 `tile 实际渲染宽度 × devicePixelRatio` 计算所需物理像素，取不小于需求的最小档位（300 / 400 / 600），保证永远是缩小而非放大，画面锐利。图片由苹果 CDN 缓存，二次访问基本秒开。

**尊重系统的「减少动态效果」。** 系统开启该设置时背景墙暂停，并在底部提示一键启用 —— 照顾前庭功能障碍与晕动症用户，同时不让普通用户误以为页面坏了。

**画布尺寸与求解基准解耦。** 诗页版式的格子尺寸仍用 `L0 = 2400` 求解（得 `s = 654.67`，与方形分支逐位相同），
纸页和画布是在网格外围向外扩出来的。所以「换版式」不改变任何一张封面的像素尺寸 ——
回归测试里有一条断言只测这个差值，必须为 0。

**布局与绘制共用同一套测量。** 字号、折行数、大小写判定若在布局和绘制里各算一遍，必然漂移。
现在统一由 `wrapTitle` / `measurePoemTitle` / `isCapsFont` 算出，写进布局返回值，绘制端直接取用。

**诗页的质感全靠代码画。** 底色 + 两张纸页 + 双线框 + 投影，没有任何背景图片。
内缩的第二道线是识别点：单线像相框，双线才像印在纸上的版心。极简白主题下白纸压白底，
真正分开两层的是 `shadowBlur = outerPad × 0.55` 那层落影，不是填充色。

**字体必须显式 `document.fonts.load()`。** `document.fonts.ready` 只等待「已开始的」加载，
而字体要等第一次真正绘制时才懒加载 —— 只等 `ready` 的话首帧一定用回退字体画完。
另外 `@font-face` 的 `font-style` 要写 `normal`：得意黑字形本身倾斜，若声明为 `oblique` 区间，
canvas 请求 `normal` 时会匹配失败并静默回退系统字体。

**标题变大只让画布变高。** 字号联动只改变画布高度与网格起始位置，
封面尺寸与每行列数的求解过程保持不变 —— 照片本身绝不缩放。

**诗页的标题字号单独标定。** 网格与阶梯版式用 80 / 100 / 120px，诗页用 186 / 210 / 234px。
诗页字号大得多不是随手调的：它要撑满纸宽形成版心，实测最宽一行占纸内宽 1899 / 1980（96%），
再小就撑不住，再大就得缩字号。

**iTunes API 的两个传闻是假的。** `attribute=albumTerm` / `attribute=songTerm` 加与不加
结果**字节级相同**；`offset` 分页 `0/5/10` 返回**同一批**。真正能「搜全」只有一条路：
先 `search?entity=musicArtist` 拿 `artistId`，再 `lookup?id=<artistId>&entity=song&limit=200`。
`artistId` 全球统一，不需要多地区试；`limit` 上限 200。

**地区不能写死 `us`。** `country=cn` 对中国大陆不开放，中文查询返回 0 条。现在按查询语种
动态选：纯英文只打 `us`，含中日韩文字才加 `tw` / `hk`。多地区并发几乎无额外成本
（6 地区 468ms vs 1 地区 465ms），但**总请求数**才是限流关键 —— `/search` 约 20 次/分钟
软限流，超限先返空响应，继续打会升级成端点级 403（`/lookup` 仍 200）。

**单曲封面重复度极高，所以不能做封面墙。** Taylor Swift 200 首歌落在 62 张专辑上。
单曲海报的视觉主角因此必须是「排名数字 + 曲名」，九宫格版里数字字号取封面边长的 0.78 倍，
比曲名更抢眼 —— 这是有意的。

**压在封面上的文字颜色不能按主题猜。** 九宫格的排名数字逐格采样封面右下区域的感知亮度
（Rec.709 加权），反推透明度使亮度差 ≥ 0.35。同一张海报里九格数字可能是黑白混的，
因为每格封面明暗不同 —— 保证看清比保证统一更重要。

**`buildTrackLayout` 完全独立于 `buildLayout`。** 专辑三个版式的公式被逐像素断言锁死，
任何改动都会让 67 项回归失败。单曲版式写成独立函数，`renderPoster` 里一个三元表达式分流，
绘制端提前 `return` 回到主流程之前。

**为什么不能一步生成 Apple Music / 网易云歌单。** 三条路都查过：

- **Apple Music API** 建歌单需要 Apple Developer Program（$99/年）+ MusicKit，
  开发者 token 必须用 `.p8` 私钥签名 —— 私钥不可能放进纯前端页面。
- **Odesli / song.link**（跨平台链接转换）的公开 API 已于 2026-07-31 弃用，
  现在返回 `401 PUBLIC_API_ACCESS_DEPRECATED`。
- **网易云「导入本地歌单」**只解析 m3u 里的本地音频路径，不会拿 `#EXTINF` 的曲名
  去曲库匹配。纯 URL 的 m3u 导进去是空歌单。

所以导出的定位是「把排名变成一份标准清单」，最后一步匹配由各平台自己完成。
网易云那条路反而最顺：它支持「截图 OCR 导入」，而我们本来就是画图工具。

**纯文本清单必须写成 `艺人 - 曲名`，不能反过来。** Soundiiz 的文档原话是
"Use Artist - Title, with a space on each side of the hyphen" —— 它拿连字符左边当艺人
去曲库匹配。写成 `曲名 - 歌手` 会让它把曲名当艺人搜，命中率极低，而且错的版本
不报错，只是安静地给你一张错歌单。这是 1.4.1 修掉的一个真实缺陷。

**Apple 的「音乐」App 不认 m3u 里的网页链接。** 它确实有
`File > Library > Import Playlist` 菜单项，但只识别本地音频文件路径，
遇到 `music.apple.com` 这类 URL 会静默丢弃，结果是一张空歌单。
`.m3u8` 的正确用法是交给 Soundiiz，由它读直链再匹配到目标平台。

**歌单文件用 `.m3u8` 不用 `.m3u`。** `.m3u` 按 ANSI 编码，中文曲名到别的机器会乱码；
`.m3u8` 是同一格式的 UTF-8 版。曲名大量是中日韩文字时，这个区别是硬性的。

**缺直链绝不编假路径。** 手动添加的图片没有来源，这时写 `# 曲名` 注释行，
而不是拼一个空 URL —— 后者会让播放器刷一堆「文件不存在」，整个歌单看起来就是坏的。
